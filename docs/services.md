# 공동 SaaS 목록과 제작 가이드

기존 121개 도구와 회원이 등록한 SaaS는 하나의 `services` 목록을 사용한다. 홈·분야별 목록·검색에서 함께 표시하고, 제작 가이드가 있거나 없는 항목을 필터로 구분한다. `/services`는 검색 조건을 유지한 채 홈 목록으로 이동한다.

## 등록과 수정

1. 로그인한 회원은 `/services/new`에서 SaaS를 등록한다. 소개·공식 주소·분야·요금 방식과 선택적인 이미지·제작 가이드를 입력한다.
2. 새 등록은 `pending`이며 등록자와 운영자만 볼 수 있다. 운영자가 공개하면 목록·검색·사이트맵에 표시된다.
3. 공개된 SaaS는 등록자와 관계없이 모든 회원이 ‘정보 수정’에서 소개와 제작 가이드를 수정 제안할 수 있다. 초기 121개 도구도 같은 편집기를 사용한다.
4. 공개된 원본은 검토 중에도 유지된다. 변경 내용은 `service_edits`에 원본·제안본·수정 이유·기준 revision으로 따로 저장하고, 제안자와 운영자만 확인한다.
5. 운영자는 `/admin#service-edits`에서 수정 전·후를 비교해 반영하거나 보완을 요청한다. 승인 즉시 공개 내용이 바뀌며 재배포가 필요 없다. 다른 수정이 먼저 반영된 제안은 덮어쓸 수 없다.
6. 제안자는 `/me#my-service-edits`에서 상태와 안내를 확인하고 검토 중인 제안을 취소할 수 있다. 공개 전 등록은 등록자만 직접 수정·재검토 요청할 수 있다.

등록자는 자신이 추가한 SaaS만 삭제할 수 있다. 초기 도구에는 등록자 소유권을 부여하지 않는다. 운영자는 공개 중지를 할 수 있다. 운영자 권한은 기존 운영 절차(`pnpm admin <가입 이메일>`)로 명시적으로 지정하며 자동 부여하지 않는다.

## 제작 가이드와 후기

가이드는 제작 범위·대체 가능성·판단 이유·난이도·만들 기능·제외할 기능·운영 항목·제작 프롬프트를 담는다. 없는 가이드를 자동으로 생성하지 않는다. 회원 등록 SaaS도 다른 회원이 가이드를 추가할 수 있고, 기본 121개 가이드도 내용을 수정할 수 있다. 기존 기본 가이드 전체 삭제는 일반 편집에서 허용하지 않는다.

기존 글의 `tool_slug` 연결은 유지하며 신규 SaaS의 제작 후기는 `posts.service_id`로 연결한다. 공개 builds 글만 목록의 후기 수와 순위에 포함한다.

## 데이터 이전과 보존

`003-shared-catalog.sql`은 `services.catalog_slug`, `services.guide`, `posts.service_id`, `service_edits`를 추가한다. 초기 도구의 등록자 값은 NULL이고, 회원 등록에는 기존 등록자를 유지한다. 한국어 한 글자 이름(예: 룸)도 지원한다.

시작 시 공개 JSON 도구를 안정적인 ID로 최초 삽입한다. 동일 주소의 회원 항목이 있으면 검토 상태와 내용을 유지하며 연결한다. 이후 시작·배포·seed는 승인된 이름·소개·가이드·revision을 덮어쓰지 않는다. JSON은 추가 가격 근거·별칭·FAQ 등과 최초 가이드의 자료로 유지한다. 기본 정보·가이드의 운영 수정은 공동 편집 흐름으로 반영한다.

## 검증과 권한

공개 HTTP(S) 주소만 받고 주소를 정규화해 중복을 차단한다. 서버는 제출한 외부 주소를 요청하지 않는다. 이미지는 기존 5MB 제한·WebP 변환을 사용하며 본인이 올린 이미지 또는 현재 항목의 이미지만 선택할 수 있다. 제안에 새로 첨부한 이미지는 승인 전 제안자·운영자에게만 보인다.

일반 텍스트 렌더링, 세션·CSRF·요청 제한, 하루 15회 등록·수정 제한을 유지한다. 같은 회원이 같은 항목에 제출할 수 있는 검토 중 제안은 하나다. 행 잠금과 revision으로 동시 승인·등록·삭제의 충돌을 처리한다. 감사 기록에 등록·수정·검토·취소를 남긴다. JavaScript 없이도 서비스 등록·가이드 추가·수정 제안·검토 폼이 작동한다.
